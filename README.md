# Конвертер координат Севастополя

Автономное PWA для перевода координат между:

- МСК-42 «Севастополь»;
- СК-63, зона 4;
- WGS-84 (десятичные градусы и градусы/минуты/секунды).

## Реализованная логика

Расчёт перенесён из исходной книги Excel:

- эллипсоид Красовского 1940 (`a = 6 378 245`, `1/f = 298.3`);
- проекция Гаусса—Крюгера;
- МСК-42: центральный меридиан 33°, `FE = −18 001.82 м`, `FN = −4 915 002.58 м`;
- СК-63 зона 4: центральный меридиан 32.5°, `FE = 4 300 000 м`, `FN = −9 214.6921 м`;
- преобразование датума Пулково-1942 ↔ WGS-84 по 7 параметрам из книги.
- интерактивная карта Севастополя со спутниковыми снимками Esri (без ключа) и переключателем подложек: «Спутник», «Схема OSM» (с приглушающим тёмным фильтром) и наложение «Улицы и подписи» из OSM, включённое по умолчанию. Маркеры строятся по тем же формулам, что и конвертер, плюс отдельная map-only привязка, которая переключается вместе с подложкой. Наложение взято из OSM, потому что картографические сервисы с готовыми подписями (CARTO) требуют ключа, а подписи Esri выше z15 в Севастополе пусты; схема OSM даёт русские названия на всех зумах.
- привязка для спутниковых снимков Esri измерена в QGIS/GDAL по ортофотопланам МСК-42 «Севастополь» (`Gauss_Kruger`, `FE = −18 001.8 м`, `FN = −4 915 002.6 м`, центральный меридиан 33°, `GCS_Pulkovo_1942`, Красовский — совпадает с нашим МСК-42). Ортофотопланы объявлены в QGIS как `LOCAL_CS` без датума, поэтому проекция назначалась явно. Снимок Esri сравнивался с ортофотопланом на общей сетке EPSG:3857 (варп GDAL + взаимная корреляция градиентов). 14 замеров на охвате около 80 км — пять точек пользователя на z17 и z18 и шесть случайных планшетов — дали одно и то же смещение: медиана `+5,10 м` на восток (MAD `0,22 м`) и `+5,97 м` на север (MAD `1,07 м`), без разворота и масштаба. В приложении округлено до `+5,1 м` на восток (Y) и `+6,0 м` на север (X).
- привязка для схемы OSM измерена в QGIS 3.44 (PROJ) наложением чертежа «границы севастополя.dxf» (МСК-42, Пулково-1942) на геометрию OSM `natural=coastline`: 1340 совпадающих с берегом вершин дали смещение `+0,61 м` на восток и `+0,20 м` на север при разбросе (MAD) около `1,9 м`, то есть `+0,6 м` на восток (Y) и `+0,2 м` на север (X).
- подложки смещены друг относительно друга примерно на `7,3 м`, поэтому одной привязкой обе обслужить нельзя: сдвиг переключается вместе с активной подложкой. На результаты конвертера привязка не влияет.
- замеры воспроизводимы: `tools/measure-map-registration.py` (береговая линия DXF против OSM), `tools/measure-esri-offset.py` (снимок Esri против ортофотопланов; режимы `points` и `random`) и `tools/render-esri-offset-sheets.py` (листы сравнения «до/после»).
- все числа привязки с условиями замера, контролем качества и оговорками вынесены в отдельный документ [`docs/map-registration.md`](docs/map-registration.md).
- независимая проверка формул: МСК-42 → СК-63 и СК-63 → WGS-84 совпадают с QGIS/PROJ в пределах `2 см` (см. `tests/coordinate.test.ts`).

Интерфейс принимает несколько строк координат из Excel через кнопку «Вставить список» и копирует результаты обратно в табличном виде.

## Локальный запуск

```bash
npm install
npm run dev
```

Проверка контрольных точек и сборка:

```bash
npm test
npm run build
```

## GitHub Pages и офлайн

1. Создайте публичный репозиторий `coordinate_converter_local` в GitHub.
2. Добавьте удалённый адрес и отправьте код:

```bash
git remote add origin https://github.com/<ваш-логин>/coordinate_converter_local.git
git branch -M main
git push -u origin main
```

3. В настройках **Settings → Pages** выберите **Source: GitHub Actions**.
4. После отправки ветки `main` workflow [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml) сам запустит тесты, соберёт PWA и опубликует его. URL сайта появится в выводе workflow.

После первого открытия опубликованного сайта браузер скачивает service worker и файлы приложения. Затем преобразования доступны офлайн; для удобства его можно установить через меню браузера «Установить приложение». Сами тайлы карты загружаются из сети, поэтому без интернета подложка может не отображаться.

> Введённые координаты не отправляются: вычисления и маркеры формируются локально. При использовании карты сервер OpenStreetMap получает запросы тайлов для видимой области и может определить просматриваемый район.
